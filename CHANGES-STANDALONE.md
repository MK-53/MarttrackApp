# MartTrack: standalone branch

This branch turns the project into a self-contained app that no longer depends on Replit.
It was originally generated with Replit Agent and ran inside Replit's environment.

## What was removed

| Removed | Why |
| --- | --- |
| `.replit`, `.replitignore`, `replit.md` | Replit workspace config |
| `.agents/`, `.config/`, `.conversation/` | Replit Agent memory and session files |
| `.replit-artifact/` (app and API) | Replit artifact/deployment config |
| `scripts/post-merge.sh` | Replit merge hook |
| `artifacts/marttrack/server/`, `scripts/build.js`, `static-build/` | Replit's Expo Go static hosting |
| `artifacts/mockup-sandbox/` | Design preview tool that used `@replit/*` Vite plugins |
| `artifacts/marttrack/app/(tabs)/` | Unused "Replit Agent is building..." stub screens |
| `@replit/connectors-sdk` | Unused dependency |
| Linux-only binary exclusions in `pnpm-workspace.yaml` | They broke installs on Windows and macOS |
| Old `pnpm-lock.yaml` | Referenced removed packages; regenerated by `pnpm install` |

## What was changed

- **Dev script:** `artifacts/marttrack` now runs plain `expo start`. Added `android` and `ios` scripts.
- **API address:** the app reads `EXPO_PUBLIC_API_URL` instead of Replit's `EXPO_PUBLIC_DOMAIN`.
- **`app.json`:** removed the `replit.com` expo-router origin. Set bundle IDs to `com.marttrack.app`.
- **Windows compatibility:**
  - The root `preinstall` script now uses Node instead of `sh`.
  - The API `dev` script no longer uses `export`.
  - `lib/db/drizzle.config.ts` uses a relative schema path, because drizzle-kit could not match absolute Windows paths.
- **API server:** `PORT` defaults to 8080, and `start` loads a local `.env` if one exists.
- **Business Briefing screen:**
  - Fixed a crash (`Cannot read property 'map' of undefined`) when no API server was configured.
  - It now shows a clear message if `EXPO_PUBLIC_API_URL` is missing, and rejects malformed server responses.
- **Gemini provider:** the model changed from `gemini-2.0-flash` to `gemini-3.5-flash`, because Google shut the 2.0 models down on June 1, 2026. Without this, every Gemini briefing returned a 404.
- **Root scripts:** added `app:dev`, `api:dev` and `db:push`.
- **Added:** `README.md`, `.env.example` files for the app and API, and `eas.json` for Android APK builds.

## Running it (Windows CMD)

Requirements: Node 22+, pnpm 10.16+, Git, and a Postgres database (only for AI Briefing).

```
pnpm install
pnpm app:dev
```

For AI Briefing, in a second window:

```
set "DATABASE_URL=your-postgres-connection-string"
pnpm db:push
pnpm api:dev
```

Then start the app with the API address:

```
set REACT_NATIVE_PACKAGER_HOSTNAME=your-pc-ip
set EXPO_PUBLIC_API_URL=http://your-pc-ip:8080
pnpm --filter @workspace/marttrack exec expo start --lan -c
```

Users add their own provider key (Anthropic, OpenAI or Gemini) under Settings, then use Business Briefing.

## Known notes

- The core app (`artifacts/marttrack/legacy/`) is offline-first and works without the API.
- The Anthropic and OpenAI model names in `artifacts/api-server/src/providers/` were not re-checked in this pass. Provider models get retired, so check them if a briefing returns a 404.
- Never commit a real `.env` file. Only the `.env.example` files belong in git.
- Expo SDK 54 is used, so the Expo Go app must support SDK 54.
